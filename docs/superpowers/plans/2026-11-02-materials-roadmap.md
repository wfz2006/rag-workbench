# 材料文献工作台后续开发路线

日期：2026-11-02。状态：基于当前本地代码的建议路线，尚未开始实施这些新能力。

## 目标与当前起点

目标是持续将有机半导体论文整理为可核对、可复用的数据，再逐步支持图表、结构和性能预测。

目前已有原文导入、正文/SI 关联、全文分批候选提取、字段证据、人工修订/批准、CSV/完整 ZIP 导出，以及这一轮交互改进。已有测试验证主要流程，但样本为合成文献和模拟模型，尚未证明真实论文的科学提取质量。

当前缺口：真实论文基线；原始 PDF 对照视图；跨浏览器刷新恢复的草稿；可恢复的后台提取；完整包回导；跨论文的数据整理与分析；经过实测的复杂表格/OCR；图像结构识别及独立预测。

## 路线选择

| 路线 | 收益 | 代价与判断 |
| --- | --- | --- |
| 全面重做前端 | 交互自由度更高 | 需重新验证导航、状态、桌面入口和大量已有行为；当前收益不足以支撑整体迁移 |
| 真实论文驱动，逐步补齐审核与任务流程 | 每次迭代都能增加实际可用能力，继续复用现有代码 | 推荐；复杂原文区域允许局部组件，其余继续用 Streamlit |
| 先上完整图像识别和预测 | 容易快速展示功能数量 | 尚无目标口径和真实验收集，无法判断输出是否可靠；暂缓整体推进 |

建议第二条。真实论文验证与必要的工程改进并行；若数据实际位于扫描页或复杂表格，提前做对应解析验证，而非机械等待某个后续阶段。

## 迭代 A：把单篇论文核对做好（最高优先级）

**用户可见交付：** 上传论文后，可在原文旁逐项核对，不必反复切标签或寻找证据。

- 宽屏原始 PDF 与记录并排；支持跳页、缩放、点击字段查看对应引文。窄屏在原文和记录之间切换，并保留位置。
- 有可靠坐标时高亮原文区域；现有纯文本路径没有坐标时，只定位到页码和引文，不伪造精确高亮。
- 当前会话草稿改为本地持久草稿。刷新/退出后可选择恢复；恢复时比较工作区、文献、记录及基础修订，冲突草稿不覆盖新记录。
- 添加下一条待审核、记录搜索、缺失证据清单及明确的保存状态；快捷键避开浏览器和输入框的正常操作。
- 在批量新增、拆分样品等操作出现前，先明确材料、样品、器件、测试条件之间的归属规则。

**真实样本工作：** 先选择 OFET、OPV 或其他一种器件方向，以及 2–3 个指标。用 3–5 篇真实论文及 SI 建立开发样本，覆盖正文、表格、多样品和条件分散的情况。保留后续未用于调参的论文作独立验收。

**验收出口：** 一篇真实论文从导入到批准、导出完整走通；数值、单位、样品、方法/条件分别核对。报告候选精确率、漏提、样品错配和人工修订耗时。3–5 篇是开发基线，不用于宣称广泛适用的准确率。

**实施位置：** `ui/materials.py` 按原文、审核、导出拆成适度独立模块；扩展 `material_drafts.py` 与材料库迁移；保持已有记录、修订历史、证据 ID 可用。

## 迭代 B：让长任务和批量整理稳定运行

**用户可见交付：** 提取可以在后台运行，用户能切页、看进度、停止并重试失败部分。

- 本地持久任务表和工作进程；页面只提交任务、显示进度和结果，不持有长时间模型请求。
- 区分等待、运行、停止请求、已停止、失败、部分完成和完成。进程异常退出后标记中断，不长期显示“运行中”。
- 按文献及批次保存输入快照、结果与错误；绑定实际模型、接口、提示词/解析版本。优先重用已持久化的批次结果，保护人工审核。
- 批量文件错误隔离；可选择失败文件/批次重试，并在执行前说明发送范围及可能的费用。
- 刷新页面或重启程序后恢复任务列表；不在重启后自动发起付费重试。服务端已执行但本地未存下结果的请求可能重复计费，界面须明确这一不确定状态。
- 完整包回导与本地备份恢复：校验清单、版本、关联闭包、原件哈希和冲突策略；限制解包路径和大小。先在新工作区预览，避免直接覆盖现有数据。

**验收出口：** 网络中断、进程退出、重复点击、重试及切工作区后，已保存记录仍可找回；重跑不重复入库、不覆盖审核；备份可在新目录恢复并继续核对。取消不承诺撤销已发生的接口费用。

**实施位置：** 新增材料任务业务模块；扩展 `ExtractionRun` 和数据库迁移，复用聊天任务的状态展示思路，但不直接把仅存内存的聊天线程当作可恢复任务。

## 迭代 C：多篇数据表与可比分析

**用户可见交付：** 能跨论文查找和比较实验记录，形成可交付的数据集。

- 跨论文记录表，按材料、样品、器件、指标、方法、条件和审核状态筛选。
- 样品/材料别名、记录拆分、重复候选提示和冲突对照。实体拆分由真实样本需求驱动，提供旧数据迁移与回退路径。
- 将原文值、规范值、范围/误差、缺失原因、实验/计算/引用他人结果分别表示；保留原文，不静默覆盖。
- 单位、载流子类型、工作区间和统计口径的质量提示。汇总前明确比较组；不同方法和条件不默认合并平均。
- 先做分布、散点、同口径分组比较和缺失字段概览；图上记录可返回证据。原文没有报告与系统漏提分开统计。
- 批量批准限定为人工明确选择且逐项校验通过的记录，展示将要改变的范围；不提供跳过证据的“一键全批准”。

**验收出口：** 同一材料不同样品不会误合并；筛选结果与导出一致；图表可追溯到审核记录；原始单位和版本保留。

## 迭代 D：依据样本需要引入表格、结构与曲线能力

按实际瓶颈分开交付，不同时承诺所有图像都能识别。

| 能力 | 首个可交付范围 | 依据与边界 |
| --- | --- | --- |
| 复杂表格 / OCR | 表头、单位、脚注、样品归属与页内位置；扫描文字经核对再批准 | 优先验证当前已有 Docling 适配器；在隔离环境对照同批论文，成功解析不等同于正确提取。官方提供[表格导出](https://docling-project.github.io/docling/_generated/examples/export_tables/)和[OCR 配置](https://docling-project.github.io/docling/concepts/OCR/) |
| 已知分子结构 | 手工确认 SMILES 后校验、绘图、指纹与相似案例 | 可复用 [RDKit](https://www.rdkit.org/docs/GettingStartedInPython.html)；这不代表能自动识别论文中的分子图片，聚合物需另行定义表示 |
| 器件结构 | 可编辑层次示意、材料/电极/几何参数及证据 | 未报告的尺寸和层次留空；先人工核对，再增加图像候选 |
| 曲线读数 | 导入选定曲线 CSV，保存原图、轴校准、单位、图例和样品 | 先对接 [WebPlotDigitizer](https://automeris.io/docs/) 的读数工作流，不自研通用自动数字化；独立评估线性/对数、多曲线和误差 |

引入外部代码或分发模型前，单独核对依赖兼容、代码/模型许可和安装体积，不将所有资源塞进主环境或便携包。上述工具文档于 2026-11-02 核对；尚未因本规划安装或接入。

## 迭代 E：相似案例先行，监督预测按数据条件启动

先交付基于已确认结构、器件和条件的相似实验检索，输出已有结果及来源，明确不属于新材料数值预测。

监督预测的启动条件：

- 一种明确目标和可比测量口径，关键输入覆盖足够的独立论文、样品与材料体系；不按总行数机械决定。
- 按论文/批次分组，针对新材料外推再按材料/结构组拆分，避免同一实验的重复数据泄漏。
- 先比较简单基线与候选模型，保留冻结测试集，报告误差、覆盖范围和失败样例。
- 新结构、工艺或关键条件超出适用范围时拒绝给出确定数值；预测不写回实验事实表。

达到约定误差容差再开放正式预测页；否则交付相似案例和实验评估报告。

## 开发与发布约束

- 保留当前本地 UI 改动；本规划不提交、推送、改版本号或更改 GitHub 封存版本。
- 每个迭代只增量验证相关数据路径和回归；UI 验收保留 1440/700/390px、双主题、切页/刷新/失败恢复的真实浏览器用例。
- 用“高优数据丢失、串工作区、错误批准、引用越界等已知问题清零”作为发布门槛，不用“零 Bug”代替可检查的标准。
- 桌面打包放在任务、备份与依赖边界稳定之后验证；主程序与可选解析模型分开管理。
- 技术排期在取得真实样本、确定器件和目标指标后再估算。等待论文、人工标注、模型下载和外部服务不混算成已承诺工期。

## 下一轮建议范围

优先推进迭代 A 的“原始 PDF 与字段并排核对 + 草稿落盘恢复 + 真实论文基线”，同时细化迭代 B 的任务接口。没有真实 PDF 时可以先做前两项工程能力，但不能以合成数据替代最终科研验收。

需要需求方最终确定的是首批器件方向、2–3 个指标及代表论文/SI；在这些信息未定前，保留可配置模板，不将 OFET 示例写成唯一支持领域。
