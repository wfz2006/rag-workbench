# 研究问题证据板实施计划

> 供实现者按复选框执行。可使用 superpowers:executing-plans 逐项实现和验证。

**目标**　研究者围绕一个问题组织主张，随手收录问答、星图和材料分析中的原文，核对后导出能用于组会或写作的研究笔记。

**架构**　沿用当前资料目录和 SQLite。保存时冻结证据文字与出处，查看时按文件内容标识回到原件。星图的日常交互继续在浏览器内运行。

**技术栈**　使用已有的 Streamlit、SQLite、本地 ECharts、Pydantic 和 PDFium。收录、回查、导出均可离线完成。

**需求依据**　本计划按 2026-11-19 讨论确定首版范围。代码基线为 `661bf18`。首版实现及验收结果见本文末尾。

## 使用流程与取舍

例如建立问题「p(g2T-T) 在凝胶化和溶剂交换过程中发生了哪些结构变化？」。在星图选中一段原文，点「收进证据板」，选择问题和主张。首次可就地新建两者。确认后回到原来阅读的位置。在问答或材料分析中也可按同一方式收录。

证据卡默认「待核实」。用户阅读原文后可改为「支持」「反例」或「条件限制」，另写判断笔记。作者的直接观察、作者提出的机制和研究者自己的解释可以分别记录。观点相反的两条引文可以并列。每条主张显示收录数和待核实数，零证据的主张也可保留。同一段证据对不同主张可以有不同的标记。

首版导出 Markdown，阅读时直接显示文件名、原页、引文及判断。离开本机后也能辨认出处。可点击看原页的验收对象是工作台内的证据卡。

## 优先检查的五个边界

| 情况 | 用户能看到的结果 | 对应任务 |
|---|---|---|
| 快速双击或窗口重试保存 | 同一主张只生成一张相同来源的卡；既有判断保留 | 1、3 |
| 同名 PDF、正文与补充材料页码相同 | 按文件内容标识打开当时引用的原件 | 2 |
| 文件已删除、索引重建或材料记录已修订 | 保留收录时的文字、页码和修订号，说明当前能否打开原件 | 1、2 |
| 文本没有物理页码，或知识包仅映射到书籍原页 | 展示实际可用的位置；只在持有对应 PDF 时提供原页预览 | 2 |
| 在星图连续切换节点后收录 | 普通浏览不触发后端重跑，收录后仍能继续原来的阅读路径 | 3、5 |

## 首版验收记录

Windows Edge 使用原资料库的隔离副本。星图收录了 `nihms-2100300.pdf` 第 4 页，聊天入口使用同一论文第 4 页真实引文构造的离线历史记录，材料入口使用核对后批准的第 5 页观测。三个入口均经界面保存，三张卡均能打开对应 PDF 原页。服务重启后卡片和判断仍在，临时移走原件时显示缺件提示并保留摘录。导出的 Markdown 有三个收录入口、原件哈希、页码和判断笔记。
