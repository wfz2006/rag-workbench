# Materials UI reliability implementation plan

**Goal:** 让已有材料文献流程可以连续操作，保护编辑输入，避免重复新增和授权串用。

**Architecture:** 沿用 Streamlit。编辑控件即时同步到独立的会话草稿，而非依赖 form 的浏览器缓冲；数据库仍只在明确保存/批准时写入。证据选择器生成现有 EvidenceReference，不改变业务校验。

**Scope:** 本地修改，保留当前 main 起点 ea9812f；不推送、不改 GitHub、正式数据、配置或模型环境。

## 已确认问题与处理

- [x] 手工新增成功后残留旧值：保存后清空新增草稿并选中新记录；失败保留输入。
- [x] 文献切换继承发送授权：绑定原件集合、模板、接口/模型及密钥配置，变化后重新确认。
- [x] 编辑与取证需频繁切换：改为独立草稿、显示未保存状态、提供显式放弃操作；导航和返回可恢复。
- [x] 证据只能手写 JSON：增加原文块、字段、多字段引文关联控件，JSON 留作高级编辑。
- [x] 导出缺少范围反馈：显示实际条数；准备失败撤下旧下载；CSV 不被原件打包失败连带阻断。
- [x] 会话管理名称滞后：同步后台自动标题，同时保留主动输入的改名草稿。

## 验证

- [x] 先用 AppTest 复现状态错误，再修复；覆盖保存失败、重复操作、切记录/文献、授权变化。
- [x] 隔离合成论文和模拟模型，浏览器验证输入后直接切页、取证、审核、真实下载、侧栏收放。
- [x] 1440px / 700px / 390px、深浅色，无页面横向溢出和 pageerror。
- [x] 运行相关测试、Ruff、diff 检查；必要时按新证据补充检查。
- [x] 独立审查改动并记录验收结果和仍存在的限制。

## 实施选择

采用原有界面内的局部流程改进；不迁移前端框架，不在本轮同时增加预测/曲线识别。编辑草稿只存当前浏览器会话，不宣称刷新或关闭浏览器后仍保留。正式记录仍有版本锁与字段证据校验。

实际浏览器另外发现并修复输入后折叠区收起；独立审查补充了带筛选新增候选的聚焦问题。验收记录见 [材料 UI 验收](../../MATERIALS_UI_VERIFICATION.md)。
