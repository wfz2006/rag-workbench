# 材料文献迭代 A 实施计划

**Goal:** 在现有材料流程中交付原始 PDF 对照、证据跳页，以及显式恢复的本地持久草稿。

**Spec:** [后续路线](2026-11-02-materials-roadmap.md) 的迭代 A；用户已要求继续开发。

**Scope:** 仅本地开发，既有 12 个修改文件已备份到 `artifacts/materials-review-20261102/before.zip`。不提交/推送，不改正式原件、密钥或封存仓库。没有真实论文，不声称科研提取精度已验收。

## 工作拆分

- [x] 草稿库：独立 `drafts.sqlite3`，工作区隔离、版本 CAS 更新/删除、错误转换、跨实例读回测试。
- [x] 恢复交互：失焦落盘、明确保存状态、进入新会话提示恢复、普通/JSON/新增草稿隔离；旧修订仅对照，不覆盖新记录。
- [x] 原文预览：原件 SHA 校验、PDF 本地页图、页码/缩放、TXT/MD 原文、缺件和缺可选组件的局部提示；有坐标才高亮。
- [x] 核对布局：宽屏并排，窄屏可切换原文/编辑并保留输入；字段证据按钮定位主文或 SI。
- [x] 效率补齐：下一条待审核、缺证据字段提示，保持原有批准校验。
- [x] 必要验证：存储/恢复/冲突回归、旧材料 UI 流程、真实浏览器新会话恢复和窄窗口取证，独立审查。

## 数据语义

草稿不是已审核记录；恢复不自动批准。草稿与正式记录基础修订绑定，同 key 多窗口写入/删除需版本检查。恢复前可预览；保存正式记录失败不删除草稿。正式记录已保存但草稿清理失败时明确区分两者，不误报为记录保存失败。磁盘草稿写入失败时保留会话输入并显示失败。

## 依赖选择

现有 `st.pdf` 缺少初始跳页 API 且需要额外组件；使用可选本地 PDFium 渲染作为这次可核对的页图方案，不依赖浏览器插件或外部 Python。只引入这一可选组件并锁定依赖；OCR/Docling 不在本轮安装。

工程交付验收见 [迭代 A 验证记录](../../MATERIALS_REVIEW_A_VERIFICATION.md)。真实论文的科研质量验收仍待样本，未将合成测试视为该门槛已完成。
